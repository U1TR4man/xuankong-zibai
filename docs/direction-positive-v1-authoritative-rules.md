### 0.5.2 已核對到固定版本原文的條目

《御定星厯考原》四庫全書本卷三（維基文庫公有領域全文，`https://zh.wikisource.org/wiki/御定星厯考原_(四庫全書本)/卷3`）已實際讀取，下列為逐字核對通過：

- **天德**（引《堪輿經》）：「天德者正月丁二月坤三月壬四月辛五月乾六月甲七月癸八月艮九月丙十月乙十一月巽十二月庚」——十二項與 §1.3 完全一致。這是六張表中唯一無法由五合推導者，故最需要核對。
- **天德合**（引《厯例》）：「天德合者正月壬三月丁四月丙六月己七月戊九月辛十月庚十二月乙是也**四仲之月天德居四維故無合也**」——與 §1.4 完全一致，且四仲無合為原文明言，非後人歸納。按語另作「天德合者即各以其月天德所合之干為之」。
- **月德**（引《厯例》）：「月德者正五九月在丙二六十月在甲三七十一月在壬四八十二月在庚」——與 §1.5 一致。曹震圭注「以三合五行陽幹為德」佐證 §1.7 推導關係 5。
- **用途**：天德「所理之方所直之日可以興土功營宫室」、月德「取土修營宜向其方……利用其日」——方、日兩用皆有原文。

### 0.5.3 新發現一：月德合的轉錄異文

同卷《厯例》月德合條作「正五九月在辛**二六十月在巳**三七十一月在丁四八十二月在乙」。

「巳」為地支，但同條按語明言「月德合者即各以月德所合之**干**為之」，而二六十月（卯未亥）的月德為甲、甲之五合為**己**。故正字應為「己」，此本作「巳」屬形近訛字。

依接手指南 §6「有異文就保存異文，不可為了讓公式完整而自行修文」：

- §1.6 表值維持「己」（由五合推導證明）。
- 異文本身必須保存，不得當作不存在。
- 實作時若另見他本，須並列，不得默默取一。

### 0.5.4 新發現二：「戊寄艮、己寄坤」確實存在，但不屬於六德

同卷〈隂陽不將〉條有：「戊巳之幹位在中央，**戊為陽將寄於艮，已為隂將寄於坤**」。

這正是 §2.3 明文禁止的映射。修正後的認識是：

- 該寄宮**是原典，不是後人杜撰**；
- 但它綁定在「陰陽不將」這條**擇日**規則的推算脈絡中，不是通用方位寄宮；
- 因此 §2.3 的禁止依然成立，但**理由必須改寫**——不是「古法沒有這個映射」，而是「這個映射有明確歸屬，適用範圍不含六德方位」。

這同時說明：不同規則須依各自原典決定如何處理戊己，不可全局套一張寄宮表。

### 0.5.5 尚未親自核對的部分

《欽定協紀辨方書》相關條目（〈月吉神總論〉〈火星〉〈制煞要法〉〈諸家年月日吉凶神附論〉）**本輪未實際讀取原文**，僅有覆核稿提供的篇名與線上連結。覆核稿本身亦註明線上章頁未標穩定頁碼、不虛構頁碼。

## 1. 六德六張表（deterministic，可封版）

「六德」＝歲德、歲德合、天德、天德合、月德、月德合。「共名六德」為《協紀辨方書》〈月吉神總論〉原文，非現代歸納。

**層級（經覆核修正）**：不可對三家統一切分。

| 家 | 層級 | 依據 |
|---|---|---|
| 天德 / 月德 | `primary_virtue` | 〈月吉神總論〉「天德、月德方大吉」 |
| 天德合 / 月德合 | `combined_virtue` | 同上「天德合、月德合方次吉」 |
| 歲德 / 歲德合 | **同級，皆 `primary_virtue`** | 《協紀》「並屬上吉」 |

初版把六者一律按「本德／合德」二分，對**歲家**是錯的：《協紀》明言歲德與歲德合並屬上吉，不得自行把歲德合降一級。編者另有「歲德偏剛、歲德合偏柔，外事可剛、內事可柔」之說，但同時自陳「選擇家未論及此」，屬編者意通，**不得轉成 ranking 權重**。

5. 月德在同一三合局的三個月支相同。
6. 月德合在同一三合局的三個月支相同。
7. 月德合＝月德的五合干。

## 2. 空間解析：兩個必須保留的「無外方」情況

本節是第十一輪最重要的成果。**不可把所有吉神結果硬轉成 24 山。**

### 2.1 戊、己不在 24 山（無外方可映射）

24 山為：

```text
坎：壬 子 癸        艮：丑 艮 寅
震：甲 卯 乙        巽：辰 巽 巳
離：丙 午 丁        坤：未 坤 申
兌：庚 酉 辛        乾：戌 乾 亥
```

其中**沒有戊、己**。「二十四山無戊己」為《協紀辨方書》原文。

**經覆核修正的措辭**：初版由「戊己為中宮之位本無方」直接推出「該德當年／當月無方可用」，這一步過度定論。可確認的只有「不在 24 山」這個事實；「因此屬中宮、因此無方」是**對六德的應用推論**，本輪未查得任何選擇原典明文如此規定。

因此欄位名不應叫 `central_stem`（宣稱了古法定性），應改為描述觀察事實的：

```ts
kind: 'outside_24_mountains'
```

行為不變——不映射任何山、不參方向排名——但理由降級為工具保守策略，不冒充古法定例。

全枚舉後，六德命中戊或己（因而無外方）的情況共 9 例：

| 規則 | 命中 | 值 |
|---|---|---|
| 歲德 | 戊年、癸年 | 戊 |
| 歲德合 | 甲年、己年 | 己 |
| 天德合 | 未月 | 己 |
| 天德合 | 申月 | 戊 |
| 月德合 | 卯月、未月、亥月 | 己 |

這些一律回傳 `outside_24_mountains`，**不得產生任何方位 boost**。

### 2.2 天德合四仲月：官方曆例無合

子、卯、午、酉月的天德分別為巽、坤、乾、艮，官方《協紀》／《星曆考原》系統作「無合」，回傳 `none`，`reason: 'classical_no_he'`。

**不得自動補四維互合。** 另有傳統材料以乾↔艮、巽↔坤為方向上的「合」，《協紀》稱可「備一義」，但不是其曆例 default，故只保存為異文：

```ts
variantId: 'tian_de_he_corner_directional_variant'
defaultEnabled: false
rankingUse: 'research_only'
```

異文不與 default 疊加，V1 亦不提供 UI selector（與五黃四隅異文的處理方式一致）。

### 2.3 禁止自造寄宮

**V1 明確禁止** `戊 → 艮`、`己 → 坤` 或任何後天寄宮映射，除非日後另做專門考源並經使用者批准。這是 stop condition，見 §8。

**理由已經覆核修正。** 《御定星厯考原》四庫本卷三〈隂陽不將〉條確有「戊為陽將寄於艮，已為隂將寄於坤」，即這個映射**是原典而非杜撰**。但它綁定在「陰陽不將」這條擇日規則的推算脈絡中，屬該規則專屬，不是通用方位寄宮。

所以禁止的正確理由是：

```text
錯：古法沒有戊寄艮、己寄坤這回事
對：這個映射有明確歸屬，適用範圍不含六德方位
```

傳統另有納甲、五行、六壬、長生等各系統的戊己處理法，彼此不同。**不同規則須依各自原典決定，不可全局套一張寄宮表。** 未查得六德專屬寄法前，就不要猜。

### 2.4 六德精度是 24 山，不是整宮

例：月德＝丙。丙只是離宮「丙 午 丁」三山之一。**不得顯示「整個南方都是月德」**，主八宮 UI 只能表達 partial positive hit，Detail 才逐山說明（丙山：月德；午、丁：非月德）。

與第十輪的 negative coverage 對稱，另開：

```ts
type PositiveHitCoverage = 'none' | 'partial' | 'full';
```

六德實務上幾乎恆為 `partial`（只落一個 15° 山）。

### 2.4.1 精度不是全域常數：占一字 vs 飛一宮（覆核新增）

不可推廣成「所有方位規則都是 15°」。真正的原則是**看該規則原典是「占一字」還是「飛一宮」**：

| 型態 | 精度 | 例 |
|---|---|---|
| 固定神占一字 | 單一 15° 山 | 六德、歲破、月破方、三煞 |
| 飛宮神煞入宮 | 整宮三山 45° | 飛宮類；《協紀》作「震宮統甲卯乙三位」 |

修方文本的操作語言支持前者：「在中宮下羅經，定所修之方屬於何字」，並直接稱甲方、丙方、庚方、壬方。

對本專案的意義：既有的大月建／月暗建與白中殺是**入中飛宮**型規則，其空間語義本就是整宮，與 24 山層的規則不同軌。實作時不得把兩者統一成同一種精度，也不得因為新增了 24 山就回頭把飛宮規則改成單山。

## 3. 三德聚方（deterministic，可封版）

### 3.1 三德不是六德

古法「三德」特指**歲德＋天德＋月德**，**不含**三個合德。命名與實作皆不得混用。

### 3.2 有直接古例

《造命宗鏡集》卷五修方段：「甲年六月，歲德、天德、月德會於甲方」，並將「三德方」列為修吉神方的重要類型。

**覆核新增**：《新刊類編陰陽選擇合併通書大全》卷十二另有專條〈三德格〉，直接使用「**三德叢聚**」一詞，並列出四組年月：

```text
甲己年六月
丙辛年九月
乙庚年十二月
丁壬年三月
```

與 §3.3 的 120 組全枚舉結果完全吻合。因此：

- 「三德叢聚」是**古籍既有名詞**，不是現代自創 heuristic，UI 可直接使用。
- §3.3 的四組不再只是本專案的推導，另有古籍對照。
- **正名**：程式識別碼應為 `sanDeCongJu`（叢聚）。原始研究稿 §15 作 `sanDeCongJi`，初版沿用，屬誤植，實作時採正名。

### 3.3 全枚舉結果（120 組年干 × 月支）

本輪以程式全枚舉，三德同方恰有 **8 組**，對應 **4 個山**：

| 年干 | 節氣月 | 三德聚方 |
|---|---|---|
| 甲年、己年 | 未月（六月） | 甲 |
| 乙年、庚年 | 丑月（十二月） | 庚 |
| 丙年、辛年 | 戌月（九月） | 丙 |
| 丁年、壬年 | 辰月（三月） | 壬 |

**戊年、癸年不產生任何 peripheral 三德聚方**：其歲德為戊（中宮干），而天德／月德並無相應外方聚會。全枚舉確認戊、癸兩個年干在十二個月中命中數為 0。

### 3.4 用計算，不寫死

推薦 `getDirectionVirtues(yearStem, monthBranch)` 後再 `detectSanDeCongJu(virtues)`，條件為：三者皆有 peripheral mountain **且** mountain 完全相同。寫死四組較易 drift。上表只作測試 fixture。

### 3.5 天德＝月德但非三德的月份

天德與月德本身在辰、未、戌、丑（三、六、九、十二月）重合為壬、甲、丙、庚。**只有歲德亦同方時才叫三德聚方**，否則只是 `multiple positive virtues`。不得濫用「三德」一詞。

## 4. 月金匱：本輪撤回（第十三輪）

### 4.1 原算法

較早選擇文獻有「本月旺方為金匱」，按三合局帝旺：

| 節氣月 | 申子辰 | 亥卯未 | 寅午戌 | 巳酉丑 |
|---|---|---|---|---|
| 月金匱 | 子 | 卯 | 午 | 酉 |

**此表即三合局的仲支**，已由 `src/selection/branchRelations.ts` 的 `SAN_HE_GROUPS[].center` 保存。實作時**必須複用該欄位，不得新建第二張月金匱表**（整合契約 §8 的單一資料源原則）。

### 4.2 《協紀》內部的張力（覆核重大修正）

初版寫「《協紀辨方書》明確提出金匱星今亦不用」，**這是片面摘引**。獨立覆核在同一部書內找到相反方向的處理，兩處並存：

| 出處 | 立場 | 短引 |
|---|---|---|
| 〈諸家年月日吉凶神附論〉 | 不用 | 「金匱星今亦不用」 |
| 〈火星〉 | 有理、條件可用 | 「月家金匱方，今通書不載，**然亦有理**」 |

〈附論〉的理由是：金匱取帝旺，而同一帝旺位又被稱作大煞／打頭火，若一邊定吉一邊定凶即自相矛盾，故傾向「本無固定吉凶，疊吉則吉，疊凶則凶」。

但〈火星〉不但保留完整起例，還給出使用條件：「諸吉同到則吉」「四仲月與月建重疊時須避」。

因此不可宣稱《協紀》一致主張廢棄。準確的描述是**同一權威編纂本內部存在處理張力**，可能反映：

1. 不接受「金匱＝無條件固定吉」；
2. 但接受「旺方在特定條件下可利用」。

本輪沒有足夠證據替編者做更深的統一解釋，兩說並列保存。

### 4.3 V1 policy

```ts
const MONTH_JIN_KUI_POLICY = {
  calculate: true,
  display: 'detail_only',
  rankingUse: 'disabled',
  mode: 'reference_only',
  evidenceStatus: 'source_tension',   // 非「協紀否定」，見 §4.2
} as const;
```

結論與初版相同，但**理由改變**：不是「因《協紀》否定所以不用」，而是「同一權威本內部已有不用與條件可用兩種處理，且本工具不做制化與火星制法，因此沒有條件替使用者判定它此刻為吉」。UI 文字不得寫成「《協紀》認為金匱無用」。

**不得因為名字吉利就加分**——`if (direction === monthJinKui) boost()` 正是 source-critical research 要避免的「吉名即加分」。

### 4.4 但不刪資料

月金匱仍有研究價值（較早修方文獻確實使用、與三合帝旺／有氣系統相關、日後研究「旺方＋紫白＋四柱」可能有用）。**不 scoring ≠ 刪資料**，延續 81 雙星的處理方式。

## 5. severity 與模式（V1 政策）

### 5.1 construction／daily 分歧

| 規則 | construction／修方 | daily／日常 |
|---|---|---|
| 歲德、天德、月德 | active positive evidence | secondary evidence／tie-break |
| 歲德合、天德合、月德合 | secondary positive evidence | secondary evidence／tie-break |
| 三德聚方 | strong positive pattern | notable positive marker |
| 月金匱 | reference_only | reference_only |

前提一律是：**Direction constraints 沒有 structural avoid。**

### 5.2 daily 模式不得讓六德取代紫白

「三德方」最強的直接語境仍是修造、營構、取土、山方。日常模式的主要 direction quality 仍是紫白：

```text
daily：Purple White = primary；六德 = secondary evidence / tie-break
```

允許的用法是 tie-break：A、B 兩方紫白品質相近，A 同時得月德而 B 沒有 → A 可優先於 B。**不得**因單一歲德或月德就把方向直接升 priority，更不得變成「月德 > 紫白」。

### 5.3 承接整合契約：模式選擇仍未定義

`docs/gates-v1-integration.md` §5 已定：daily／construction 的使用者選擇方式尚未定義，規格確定前一律以 daily 為預設語義，construction 級 severity 只作文字說明。本輪不改變此結論，六德的 construction 級 active positive 同樣**在 UI 規格確定前不得進入 verdict**。

## 6. precedence：正面不得翻轉 structural veto

這是第十二輪最重要的成果，也是整個擇吉 engine 的 architecture invariant。

### 6.1 禁止的實作

```ts
// 明確禁止
if (sanDeCongJu) { suiPo = false; sanSha = false; }
```

《造命宗鏡集》要求「吉方必須不疊緊要殺」；《協紀辨方書》作「大煞避之，中煞制之，小煞不必論」，且即使太陽等強吉星遇某些猛煞亦不能簡單制伏。

### 6.2 Final synthesis 不用總分

```text
錯：歲德 +2、天德 +2、月德 +2、三德 +5 → 總分高即可用
對：positiveEvidence[] + patterns[]，由 precedence 決定 final status
```

禁止數值化的額外理由：**「三德」本身就是三條 evidence 的特定聚會，若三條各加分再加三德分即重複疊分。**

structural avoid 的例子：construction 模式下精確犯歲破山 → `avoid`，即使三德聚方且年月日時紫白俱佳，仍不得自動翻轉。

### 6.3 正面 evidence 必須支援多值

一個山可同時是歲德、天德、月德、天德合……故必須是陣列：

```ts
positiveEvidence: DirectionVirtueEvidence[];   // 對
positiveVirtue?: string;                       // 錯
```

與第十輪 negative hits 的陣列設計一致：overlap 並列顯示，不做數值相抵。

### 6.4 「六德能否制支煞」的文本辯論：V1 不判定

部分傳承作「六德俱走天干，不能制地支方煞」，但《協紀》編者明確批評此說不對，理由是「支煞正可由干制」。這意味真正的制煞不是「吉神 vs 凶神」的 boolean，而要看干犯干制、支犯支制、三合犯三合制、旺衰與四柱。

由於 V1 不做完整制煞、不採納音、不做四柱制化成局：

```ts
virtueCancelsKiller = false;
```

metadata 須明示：「古法另有制化理論，本版本不自動判定制煞成功。」這**不是**認定「六德永不能制煞」，而是 V1 不具備替使用者判定「已制化成功」的條件。UI 文字不得寫成「六德不能制煞」。

## 8. Stop conditions

實作前或實作中遇到下列情形，必須停止並詢問使用者：

5. 要引入「修造／日常／葬事」模式切換而 UI 規格未定義使用者如何選擇。
6. 要讓任何吉神自動取消歲破、三煞、大月建、破日或時破。
7. 要建立「命中 2 個六德 ＝ priority」「3 個吉神 ＝ 固定加分」這類古法未明載的硬閾值。
8. 要把月金匱重新升為正面吉方。
